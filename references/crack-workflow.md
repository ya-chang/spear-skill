# 完整破解链路（crack-workflow）

目标：从拿到目标到交付 patch/注册机的**端到端标准流程**。这是 `spear` 技能的核心串联，把脱壳、反调试、VM、去混淆串成一条可执行链路。

## 一、标准链路

```
拿到目标程序
  ↓
① 识别保护类型（熵值/段名/字符串/CFG）
  ↓
② 脱壳（UPX 直接脱；商业壳动态 dump OEP）
  ↓
③ 反调试绕过（ptrace/PEB/时间/TLS，先入口级再运行中）
  ↓
④ 字符串提取（解密运行时字符串，降噪声）
  ↓
⑤ 控制流清理（虚假控制流 → OLLVM 平坦化 → 间接调用）
  ↓
⑥ VM 字节码逆向（若校验在 VM 里，最后处理）
  ↓
⑦ 定位 CHECK_FN（校验/激活/注册入口）
  ↓
⑧ 还原算法（加密/哈希/签名，写成独立实现）
  ↓
⑨ 交付：打补丁 或 写注册机
  ↓
⑩ 验证：校验通过 + 行为等价 + 可复现
```

## 二、分步要点

### ① 识别
```bash
python3 -c "import math,collections,sys; d=open(sys.argv[1],'rb').read(); f=collections.Counter(d); h=-sum((c/len(d))*math.log2(c/len(d)) for c in f.values()); print('entropy',round(h,4),'PACKED' if h>7 else 'normal')" target
strings -a target | grep -iE "upx|vmprotect|themida|vmp|ollvm"
readelf -S target | grep -iE "upx|vmp|themida"
```

### ② 脱壳
- UPX：`upx -d target -o unpacked`
- 商业壳：mprotect 断点 + 单步到 OEP，dump 内存（见 `unpacking.md`）
- Android 壳：Frida 抓运行时 DEX（见 `unpacking.md`）

### ③ 反调试绕过
先绕入口级（ptrace/BeingDebugged），再绕运行中（时间/TLS/VEH），最后处理内存完整性校验。见 `anti-debug.md`。

### ④ 字符串提取
静态 strings 少但运行时有串 → 找解密函数，GDB/Frida hook 出口收集明文。见 `deobfuscation.md`。

### ⑤ 控制流清理
顺序：虚假控制流 → OLLVM 平坦化 → 间接调用。用 Frida Stalker 覆盖率 + angr 恢复真实块。见 `deobfuscation.md`。

### ⑥ VM 逆向
若校验逻辑在 VM 里，按 dispatcher → opcode → 反汇编器还原。见 `vm-bytecode.md`。

### ⑦ 定位 CHECK_FN
线索：字符串 "register/license/key/激活/注册"、`strcmp`/`memcmp` 热点、返回值分支、`perf` 热点函数。

### ⑧ 还原算法
识别算法（见 `deobfuscation.md` 算法特征表），还原成独立 Python/C 实现，能复现原程序的校验结果。

### ⑨ 交付
**打补丁**：
- 记录 `OFFSET` + `PATCH_BYTE` + 原始字节。
- 只改目标校验分支，保留其他逻辑。
- 用 r2/capstone 写字节，保留回滚。

**写注册机**：
- 用还原的算法独立实现，生成有效序列号/卡密。
- 回填原程序验证通过。

```python
# keygen 骨架（按还原的算法填）
def generate_key(user):
    # 还原的算法：从用户信息算出校验码
    return serial
```

### ⑩ 验证
- 校验通过（patch 后 / 注册机生成的 key 能通过）
- 行为等价（正常功能不受影响）
- 可复现（独立实现 + 验证命令）
- 多输入稳定

## 三、常见保护组合的快速路径

| 保护组合 | 路径 |
|---|---|
| 仅 UPX | ② 直接脱 → ⑦ 定位 → ⑨ 交付 |
| UPX + 反调试 | ② 脱 → ③ 反调试 → ⑦ → ⑨ |
| 商业壳 + 反调试 + 字符串加密 | ② 动态脱 → ③ 反调试 → ④ 字符串 → ⑦ → ⑨ |
| + OLLVM 平坦化 | ⑤ 去平坦化 → ⑦ → ⑨ |
| + VM 保护 | ⑥ VM 逆向 → ⑦ → ⑨ |
| Android 壳 | ② Frida 抓 DEX → 重组签名 → ⑦ → ⑨ |
| .NET + 混淆器 | dnSpy 反编译 → 去混淆 → ⑦ → ⑨ |

## 四、铁律

1. **原样本只读**，产物记哈希，保留回滚。
2. **证据优先**，不硬编码地址/偏移/密钥。
3. **两层确认**，关键结论双工具交叉验证。
4. **不破坏业务**，只改目标校验，保留正常路径。
5. **完成标准**：校验通过 + 行为等价 + 可复现，不是"能安装"。

## 五、验证清单

- [ ] 脱壳完成：脱壳后文件熵值回落，`file` 识别正常，能运行（详见 unpacking.md 验证）
- [ ] 反调试绕过：调试器能附着、设断点、单步，程序不闪退（详见 anti-debug.md 验证）
- [ ] VM/混淆还原：字节码/混淆逻辑还原，算法可复现，行为等价（详见 deobfuscation.md/vm-bytecode.md 验证）
- [ ] CHECK_FN 定位：校验函数/加密入口定位准确，交叉引用可追溯
- [ ] Patch/注册机：patch 字节正确或注册机输出通过校验，校验通过
- [ ] 行为等价：修改后程序功能与原版一致，登录/授权/网络正常路径未破坏
- [ ] 可复现：同一套 patch/注册机在同版本样本上重复验证通过

## 五·五、代码骨架：破解流程自动化检查脚本

> 可运行的 Python 骨架，按破解链路逐环节检查产物，输出完成度报告。关键路径按样本替换。

```python
# crack_check.py — 破解流程验证骨架（Python）
# 按标准链路逐环节检查产物，输出完成度

import hashlib
import os
import subprocess

def sha256_file(path):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        for chunk in iter(lambda: f.read(8192), b""):
            h.update(chunk)
    return h.hexdigest()

def check_unpack(path):
    """检查脱壳产物"""
    # 熵值检查（简化：用 file 识别）
    r = subprocess.run(["file", path], capture_output=True, text=True)
    output = r.stdout
    if "ELF" in output or "PE32" in output:
        print(f"[check] unpack: OK ({output.strip()})")
        return True
    print(f"[check] unpack: FAIL ({output.strip()})")
    return False

def check_patch(original, patched):
    """检查 patch 产物：与原版哈希不同，但功能等价"""
    h_orig = sha256_file(original)
    h_patched = sha256_file(patched)
    if h_orig == h_patched:
        print("[check] patch: FAIL (no change)")
        return False
    print(f"[check] patch: OK (hash changed)")
    return True

def check_runnable(path):
    """检查可运行性（简化：检查文件可读且非空）"""
    if os.path.getsize(path) > 0:
        print(f"[check] runnable: OK ({os.path.getsize(path)} bytes)")
        return True
    print("[check] runnable: FAIL (empty)")
    return False

def main():
    original = "[ORIGINAL]"
    unpacked = "[UNPACKED]"
    patched = "[PATCHED]"

    results = []
    results.append(("unpack", check_unpack(unpacked)))
    results.append(("patch", check_patch(original, patched)))
    results.append(("runnable", check_runnable(patched)))

    print("\n=== 完成度报告 ===")
    passed = sum(1 for _, ok in results if ok)
    for name, ok in results:
        print(f"  {name}: {'PASS' if ok else 'FAIL'}")
    print(f"\n完成度: {passed}/{len(results)}")

    if passed == len(results):
        print("[done] 全部检查通过，破解链路完成")
    else:
        print("[warn] 部分检查未通过，回到对应环节修复")

if __name__ == "__main__":
    main()
```

运行：`python3 crack_check.py`。验证：输出完成度报告，各环节 PASS/FAIL 明确，全过才算破解链路完成。

## 六、离线校验器回环与密钥空间可行性评估

> 场景：算法全公开、数据全 dump，唯一变量是 key——先把校验逻辑离线复刻，再算清楚「撞 key / 撞 flag / 找泄露」三条路各自的可行性，别把算力押在物理无解的空间上。

### 6.1 离线校验器：不碰原载体复刻校验逻辑

把载体（WASM/VM/壳）里的校验算法用纯软件复刻成离线 checker，**不加载原载体**直接跑。实战数据：Node 单核 62 万次/秒的离线校验器，跑在普通机器上，速度远超任何动态载体。

**回环自证流程**（防「逆错了自己不知道」）：

```
1. 用构建源码/已知答案造 fixture：已知 key + 已知 flag
2. 走完整加密流程，产出 blob
3. 用复刻 checker 还原 salt/rounds/commit，并解回 flag
4. 比对：recovered salt == real / rounds == real / commit 匹配
5. 输出 FLAG ROUNDTRIP: PASS 才算算法复刻正确
```

### 6.2 密钥空间搜索可行性评估（先算账再动手）

key 空间先做量级估算，再决定撞不撞：

```
key = 16 位可打印 ASCII，字符集 94 → 94^16 ≈ 3.5×10^31
校验器实测速度：单核 62 万次/秒

算力               撞完需要
单核 62 万次/秒    约 1.8×10^18 年
32 核全开          约 5.6×10^16 年
GPU 100 亿次/秒    约 1.1×10^14 年
（宇宙年龄 1.38×10^10 年）
```

**判据**：估算结果超出物理可行范围（远超宇宙年龄）→ 撞 key 路线直接判死，转向撞 flag / 找泄露。不要拿「搜索空间大」当难度，那是加密的保密性，不是加固的对抗强度。

### 6.3 哈希预言机离线验证（撞 flag 的 oracle）

当校验端公开了「结果哈希」（如 `SHA256(flag) == 已知值`），且与 key 无关、离线可验：

1. **明文长度推断**：从打包产物长度反推明文长度（实战：pack 88 字节 = 42 固定头 + clen → flag 明文恰好 46 字节 = `FLAG{` + 40 + `}`）；
2. **离线验算**：纸上写候选 flag，本地算哈希对一下就知道对不对，**不需要运行载体、不需要 key**；
3. **词表轰炸顺序**：主题词表（项目名/leetspeak/双词三词/整句短语）→ 哈希形态词源（`SHA1(词)` / `MD5+MD5[:8]` / `SHA256[:40]`）→ 真实词典与常见密码表（google-10000、10k-most-common、rockyou）。三波全灭说明答案来自人工随机字符串，词表路线预期低。

### 6.4 泄露挖掘（git 历史 / 包仓库 / CI）

- `git fetch --unshallow` 拉全历史，`git log -G 'FLAG{'` / `-S` 搜明文（区分 fixture 与真实值）；
- `git reflog` / `git fsck --unreachable --dangling` 找误提交的悬空对象；
- 包仓库（npm 等）深挖：注意下载被截断时重试拿完整包；
- CI workflows 的 secrets 记录：某版本没有 secrets → 说明本地构建后提交，痕迹在本地；
- 作者自写的 lint/防泄露工具文件名本身就是「已知薄弱点」的旁证（如防已知明文攻击的 lint，说明作者自己知道该处有裂缝）。

### 6.5 已知明文攻击

用构建源码造「已知答案」的明文，走完整加密流程与真实 blob 对拍，找不依赖 key 可观察的结构。若结构被 `mask = SHA256(key)` 类设计盖死、无任何泄露点——**这一仗输的是加密本身，不是加固**，如实记录，不硬撑。

### 6.6 验证

- [ ] 离线校验器复刻完成，用 fixture 回环自证 PASS（salt/rounds/commit/flag 全部吻合）
- [ ] 密钥空间量级估算表产出，物理可行性判定明确（撞/不撞）
- [ ] 哈希预言机离线验证流程跑通，明文长度推断与实际一致
- [ ] 词表三波轰炸记录命中数（无命中也记录，作为路线判死依据）
- [ ] 泄露挖掘清单（git/包/CI）逐项排查，无泄露则如实记录
- [ ] 已知明文攻击对拍结论明确：有泄露点则利用，无泄露点则记录判负原因

## 七、逆向作战流程（先定义赢，再动手）

### 阶段 0：先定义"赢"

没有验收标准就不要打开 IDA。开工前写下一句话：「当 ______ 时，任务成功；验收方式是 ______（可执行命令/可复现操作）。」

| ❌ 伪目标 | ✅ 可验收目标 |
|---|---|
| 破解这个软件 | 用任意用户名 + 生成的码，在干净虚拟机上启动即显示"已注册"，功能可用、无到期提示 |
| 搞定这个反爬 | 同一 session 连续 200 次请求成功率 > 98%，间隔 3s，换 IP 后仍成立 |
| 导出聊天记录 | 全部条目转成可播放文件，逐片核对，失败清单为空 |
| 看懂这个壳 | 能写出入口 → 解密 → 跳到 OEP 每步地址与依据，并用 dump 文件独立验证 |

同时定义"**不许破坏的东西**"：用户要求保留的功能、原始文件（先备份）、系统稳定性。

### 阶段 1：侦察画像（先画全，再深入）

### 阶段 2：闸门地图

逆向的本质是找**决策点**：

```
输入(用户/文件/网络)
   → 规范化 → 解码 → 反序列化
   → 校验① (格式/长度/校验和)
   → 校验② (密码学: HMAC/RSA/对称解密)
   → 校验③ (业务规则: 版本/功能位/机器绑定/次数)
   → 决策 → 后果 (解锁 UI / 放行请求 / 写配置)
```

每个节点标注三件事：**输入从哪来、输出到哪去、失败时的表现**。报错文本、日志、UI 文案都是免费的节点标签。

### 阶段 3：选点——改哪里最便宜（按成本从低到高）

| 优先级 | 改动形态 | 成本 | 风险 | 例 |
|---|---|---|---|---|
| 1 | **改数据/配置/状态**，不碰代码 | 极低 | 极低 | SQLite 触发器拦状态更新；改 INI 跳过引导 |
| 2 | **改返回值**（恒 true / 需要的 enum） | 低 | 低，注意调用方还读别的字段 | `B0 01 C3`、`B8 03 00 00 00 C3` |
| 3 | **改条件分支**（`jne`→`je` / nop 跳转） | 低 | 中：可能只绕过症状 | `bne.un` → `pop pop` |
| 4 | **改校验值**（伪造 CRC/HMAC/签名） | 中 | **高**：校验值常与分支耦合 | 伪 CRC64 → `BadImageFormatException` |
| 5 | **改算法常量**（RSA 模数、S-Box、字母表） | 中高 | 中：需重验整条链 | Navicat 改一个立即数，模数可分解求 d |
| 6 | **重写算法 / 造 keygen** | 高 | 高：必须过原程序验收 | 见下节 |

### 阶段 4：工具降层决策树

先判断保护对什么敏感，再选工具，顺序不能反：

```
保护对什么敏感？
├─ 语义（逻辑、返回值、IL 指令含义）
│   → IL 级（Cecil/dnlib/ILSpy 回编）或源码级修改；仍可能被完整性校验捕获
├─ 字节偏移 / 文件结构（Babel、自校验、层间派生）
│   → 必须降字节层：读文件 → RVA 换 FileOffset → 等长替换 → 写回，不重序列化
├─ 运行时内存（VMP、加密狗、内存校验）
│   → 运行时 hook / dump / 内存补丁；静态改文件往往无效
└─ 外部（服务端、云端许可）
    → 本地改动无意义，转协议层或数据层
```

判定实验（很便宜，务必做）：用高层工具改一次看报什么错。`InvalidProgramException` → 保护在读字节级结构 → 立刻降层；程序正常启动但功能没变 → 改错了点（有第二处判断）；崩在无关处 → 触发了完整性/派生链。

### 阶段 5：补丁纪律

**等长替换，永远先算栈平衡**：

| 原指令 | 安全替换 |
|---|---|
| `stsfld`(5B) | `pop` + 4×`0x00`（弹掉压入值，保持栈平衡） |
| `bne.un` | `pop` + `pop`（比较用的两个值都弹掉） |
| `call`(5B) | `nop`×5 |
| 函数整体(≥6B) | `B8 imm32; C3`（优于借库函数序言，不依赖外部符号） |
| ARM64 分支(4B) | `0x14000000 \| (off>>2)`：`BR Xn` → `B imm` |

字符串补丁：新串长度 ≤ 原串，短的部分用 `0x20`（空格）填充，**绝不用 `0x00`**（C 字符串截断，Kindle `jb.so` 踩过）。

特征码定位，不用硬编码 RVA：取唯一字节序列（变化立即数用通配）做签名，每次启动/构建都重新搜索；RVA↔FileOffset：`offset = RVA - VirtualAddress + PointerToRawData`；重定位守卫：任何落在 [PreferredBase, +SizeOfImage) 内的 dword 都会被 delta 平移，写死绝对地址的补丁在 ASLR 后必崩。

平台收尾：macOS 改完必须 `codesign --force --sign -`（ad-hoc），关掉 Sparkle 自更新；Electron 改 `app.asar` 后重新 `asar pack`，注意 `integrity` 字段；Windows Authenticode 会失效（除非目标不校验）。

**幂等脚本**：交付 `patch / rollback / status` 三合一脚本——先备份+记录哈希，打补丁前校验哈希已打则拒绝，status 能回答当前状态，回滚不依赖网络/临时目录（用 `$PSScriptRoot`/`%~dp0`，别硬编码绝对路径）。

### 阶段 6：止损信号（出现任一，立刻换路）

| 信号 | 含义 | 该做什么 |
|---|---|---|
| 连续两次修复都产生新副作用 | 因果地图错了 | 停下重画链 |
| 改 A 崩 B，改 B 崩 A | 存在派生/耦合 | 转结构分析：谁派生了谁 |
| 一个假设验证三轮还是"可能" | 不可证伪 | 废弃该假设 |
| 目标值在静态产物里搜不到 | 运行时生成/服务端下发 | 转运行时捕获 |
| 密钥候选空间 > 10^6 且无结构可利用 | 求逆不经济 | 转"等 key"或"接管出口" |
| 所有本地路径都通但功能仍失败 | 有服务端二次校验 | 转协议层，或明确告知不可行 |

### 阶段 7：验收（三层，缺一层都不算完）

1. **功能验收**：干净环境（新虚拟机/新用户/清缓存）达成。
2. **副作用验收**：原版能做的事逐条过一遍。任何"别的怪现象"都算未完成。
3. **回归验收**：≥3 条不同输入路径（正常/边界/垃圾值）不崩；连续运行稳定；换机器/时间/账号仍成立。

**原版配对法**：任何"这肯定是 bug"的判断，先用未修改原版跑同样操作。原版也这样 → 不是你的问题，假设死。

### 反模式速查

| 反模式 | 后果 |
|---|---|
| 先跑脚本再读代码 | 不知道自己在改什么 |
| 用 `find(b"XXXX")` 四字节搜结构 | 命中数据区假标记，读出天文数字长度 |
| 一次样本定契约 | 换输入就崩；参数要多样本取样 |
| 靠 GUI 显示判断成功 | UI 文案来自缓存字段，与服务端判定脱钩 |
| 只改一处就宣布完成 | 存在第二处独立判断 |
| 提权解决一切 | `RunAsInvoker` 往往更优 |
| 用无限重试掩盖不确定性 | 长任务必须有唯一判定 + 失败即停 + 断点续传 |

## 八、原生客户端授权 / 注册机

适用：注册码、激活码、licence 文件、云许可 token、硬件绑定、试用期。

### 一、先定位"授权形态"，再选攻击面

| 形态 | 特征 | 攻击面 |
|---|---|---|
| **本地算法** | 输入 → 解码 → 校验，全程无网络 | 还原算法 → keygen（收益最高，可跨机器） |
| **本地校验 + 内嵌公钥** | 有 RSA/ECDSA 验签 | 改模数/改验签结果；私钥泄露则直接签 |
| **云许可** | HTTP 请求 + 本地缓存 | 抓手在**缓存解密**，而非验证逻辑 |
| **硬件绑定** | 读 MAC/磁盘序列号/TPM | 找"采集点"，改采集返回值比改校验便宜 |
| **时间型试用** | 存首次运行时间、运行计数 | 找写盘点（注册表/文件/隐藏流），一次写多处要全改 |

判据来源：导入表（`bcrypt`/`crypt32`/`advapi32`/`wininet`）+ 字符串（`http`、`Serial`、`Expire`、`Trial`）。

### 二、算法识别：靠证据链，不靠猜名字

真实案例推断链（结论：Blowfish-CBC）：

| 证据 | 观测 | 推论 |
|---|---|---|
| 块长 | 每次处理 8 字节 | 64-bit 分组（排除 AES） |
| 密钥长 | 常量表 24 字节 | Blowfish 可变长密钥（16~56） |
| P-array/S-Box 初始化 | 内嵌 π 小数常量表 | Blowfish 标准初始化向量 |
| 调用方向 | 解密时 IV 来自密文前 8 字节 | CBC |
| RTTI / 类型名 | 残留类名含 `BlowFish` | 强确认 |

通用证据维度：**块长**（8/16/流式）、**密钥长度与派生**（直接/MD5 截断/PBKDF2/SHA-256）、**常量指纹**（S-Box/IV/轮常量，与公开实现逐字节对拍）、**IV 来源**（固定零/密文前 N 字节/随机前置）、**padding 形态**（PKCS#7/零填充/自定义 `pt || 00*pad || u64le(pad)`）、**方向**（加密 vs 解密）、**RTTI/类型名/异常字符串**。

> **自定义 padding 是"算法对但结果错"的头号来源。** 真实案例 `pt || 00*pad || u64le(pad)`，pad 值写在末尾 8 字节小端——少这一条，解密永远差几个字节。

**RSA 识别与利用**：

| 特征 | 说明 |
|---|---|
| 密文前 2 字节 `00 01 FF...` | **类型 1 padding**（私钥加密/验签），说明是"验签"不是"解密" |
| 大奇数模数 + 固定指数 65537 | 公钥内嵌 |
| 验证函数返回 bool | 上下文有 `RSA_verify` 类符号 |

**模数可分解攻击**：程序把模数硬编码为立即数时，改一位立即数（如 `B2 53 → 54`）得到 N′，若 N′ 可被小素数整除（如 47），可构造等价私钥：

```
N' = N + 2^122,  N' % 47 == 0  →  可分解 → 求出 d  →  用 d 签任何码
```

关键：**改常量而不是改逻辑**，签名仍然"真"通过验签，副作用最小。

### 三、定位：特征码 > 硬编码 RVA

1. 取唯一字节序列（变化立即数用通配 `??`），长度 12~24 字节足够
2. 每次运行都重新搜索，不要记死地址
3. RVA↔FileOffset：找到所在节 → `offset = RVA - VirtualAddress + PointerToRawData`
4. 重定位守卫：镜像范围内的 dword 会被 delta 平移，写死绝对地址必崩

**补丁点选择顺序**（成本从低到高）：返回值常量（`B0 01 C3` / `B8 imm32 C3`）→ 条件跳转（nop/反转）→ 立即数（模数/密钥/日期/次数上限）→ 校验值（**慎用**，常与分支耦合）→ 重写算法。

### 四、运行时捕获：静态拿不到就"等它算出来"

用 `DEBUG_ONLY_THIS_PROCESS` 启动目标，在特征码处下断，读寄存器/栈上已经算好的明文与密钥。特征码示例：`2B F7 03 F3 56 FF D0`（loader 交接签名）——用特征码而不是地址，跨版本仍可用。

运行时捕获的四种站位：

| 站位 | 抓什么 |
|---|---|
| 解密函数入口 | 密文、长度 |
| 解密函数出口 | **明文（最值钱）** |
| 比较指令前 | 期望值 vs 计算值 |
| 写缓存前 | 最终被信任的 token 结构 |

次级手段：inline hook（改函数头 5 字节跳板）、`WriteProcessMemory` 改内存常量、硬件断点（DR0-DR3）避开 `INT3` 检测。

### 五、明暗信号：别把 UI 当结论

| 信号类型 | 例子 | 可信度 |
|---|---|---|
| UI 显示"已注册" | 标题栏去掉 `(Trial)` | **低**：来自缓存字段，与真实判定脱钩 |
| 功能真的可用 | 导出不加水印、批量不受限 | 中 |
| 服务端接受 | 联网功能正常 | 高 |
| 进程行为变化 | 不再写试用计数、不再弹窗 | 中 |

**验收必须用"高"那一档。** UI 只是症状。

### 六、keygen / 注册机自验清单

- [ ] 生成的码被**原程序**接受（不是被我的验证脚本接受）
- [ ] 干净机器（无我的补丁）也接受
- [ ] 换用户名 / 换机器码 / 换时区 / 换语言仍接受（或明确说明绑定关系）
- [ ] 边界：空用户名、超长、含非 ASCII、含分隔符
- [ ] 拒绝路径正确：故意错的码必须被拒（**否则说明校验被我打死了**）
- [ ] 与官方正版码格式一致：长度、分隔符、校验位、大小写

> 最后一条特别重要：**"什么都接受"不是破解成功，是校验被我打死了。**

### 七、平台差异速查

| 平台/编译器 | 要点 |
|---|---|
| **Delphi** | 方法表在 `.data`：`len|addr|len|name` 连续排列，可据此恢复类结构 |
| **FPC/Lazarus** | bool 返回值走 **AL**：`B0 01 C3` |
| **MSVC x64** | 返回值走 EAX/RAX；x64 无 `stdcall` 名字修饰 |
| **macOS/ObjC** | `dlopen` + `class_copyMethodList` 拿 IMP → 减 ASLR slide 得文件偏移；改完必须 `codesign --force --sign -`；关 Sparkle 自更新 |
| **ARM64** | 分支补丁 `0x14000000 \| (off>>2)`；字符串等长替换补 `0x20` 不补 `0x00` |
| **.NET 混编** | 见 `dotnet.md`（等长 IL 补丁） |

### 八、云许可的特殊性（GlassWire / Electron 类）

云许可的"验证"在服务端，本地只存 token，攻击面是**缓存**：找本地缓存（SQLite/protobuf/JSON/注册表）→ 找解密函数（常是对称算法+固定密钥）→ 手工造"合法"token 结构（protobuf 手写序列化完全可行）→ 用程序解密函数反推加密或直接 hook 出口替换明文。

真实案例要点：
- token 是 **protobuf + Base64 存成 TEXT 字段**（不是 BLOB，别按二进制读）
- 时间字段格式 `%Y-%m-%dT%H:%M:%S`，**没有 `Z`**（多一个字符就解析失败）
- 写回注意 SQLite 类型亲和性；用 `LIKE` 查询会命中 BLOB 空行（真实坑）
- 校验成功有多个信号，UI 的"已授权"可能是缓存渲染
